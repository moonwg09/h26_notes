# 💻 컴퓨터 구조 및 OS 기초 정리

## 🔌 하드웨어의 발전과 논리 회로
* **PCB (Printed Circuit Board)** : 인쇄 회로 판
* **소자의 진화**: 다이오드 → 트랜지스터(TR) → 집적회로(IC) → **Chip**
    * **다이오드**: 전류를 한 방향으로만 흐르게 함
    * **트랜지스터(TR)**: 전기의 흐름을 끊거나 이어주는 스위치 역할. 이 '0'과 '1'의 상태가 디지털 신호의 기초가 된다.
    * **집적회로(IC)**: 수많은 트랜지스터와 회로를 하나의 작은 판(칩) 위에 모아놓은 것
* **스위치와 연산**:
    * **Switch**: 전기 신호를 0과 1로 변환
    * **TR (Transistor)**: 현대 반도체의 핵심 스위치
    * **부울 대수 (Bool Algebra)**: 논리식을 통해 산술 연산 가능
    * **NAND (Not AND)**: 반도체 효율이 좋아 **NAND Flash 메모리**의 기반이 됨

---

## ⚙️ 소프트웨어와 운영체제 (OS)
### 1. 소프트웨어의 진화
* **Firmware**: 과거 특정 하드웨어의 단순 동작 수행 목적
* **Embedded SW**: 기능 확대 및 회로 복잡화로 인해 소프트웨어 비중이 커진 형태
* **OS (Operating System)**: 복잡해진 시스템을 관리하기 위한 운영체계 도입

### 2. 운영체제의 계보 및 특징
* **뿌리**: `UNIX` → `Linux` (오픈소스, 보안 강화) / `MS-DOS` (16비트, IBM-MS 협업)
* **최신 OS**: Android, iOS, Windows
* **배포판 (Distribute)**: 커널 + UI + 기능을 합쳐 상품화
    * **Red Hat**: 가장 오래된 기업용 배포판
    * **Ubuntu**: 사용자 점유율이 가장 높음
* **LTS (Long Term Service)**: 4~5년 이상의 장기 기술 지원 버전 (예: Ubuntu 24.04)

---

## 🖥️ 가상화 및 시스템 구조
* **메인프레임 vs 콘솔**
    * **메인프레임**: 실제 데이터 처리를 담당하는 컴퓨터 본체
    * **콘솔**: 명령을 입력하고 결과를 확인하는 입출력 장치 (모니터, 키보드)
* **Virtualization (가상화)**
    * **Clustering**: 여러 대의 컴퓨터를 가상화하여 1대처럼 사용
    * **Host OS**: 가상화 프로그램의 기반이 되는 실제 설치 OS (예: Windows)
    * **Guest OS** : 가상화 프로그램 위에서 돌아가는 '가짜' OS (예: Ubuntu)

## 🏗️ 운영체제의 3요소: 상품이 되는 과정
### 1. 커널(kernel) : 자동차의 엔진
* **역할**: 하드웨어(cpu,메모리,디스크)를 직접 제어하는 최하단 소프트웨어
* **심장인 이유**: 커널이 죽으면 운영체제 전체가 멈춤. 메모리를 나눠주고 프로세스 순서를 정하는 핵심 역할 수행

### 2. UI(user interface) : 자동차의 외관과 대시보드
* **역할**: 사용자가 커널에 명령을 내릴 수 있도록 돕는 통로
* **종류** :
    * **CLI**: 명령어를 직접 입력하는 방식(예: 터미널, cmd)
    * **GUI**: 아이콘과 마우스를 사용하는 방식(예: 바탕화면, 창)

### 3. 기능(Apllication) : 편의 사양
* **역할**: 사용자가 목적을 달성할 수 있도록 도와주는 기본 도구들
* **포함 요소**: 파일 탐색기, 웹 브라우저, 설정 창, 보안 프로그램, 패키지 매니저 등

## 🧠 CPU (Central Processing Unit)
### 구성 요소
* **ALU (Arithmetic Logic Unit)**: 산술 논리 연산 장치
* **Control Unit**: 제어 장치
* **Registers**: 초고속 임시 저장 장치

---

## 🧠 현대 CPU의 '하이브리드' 구조
### 1.P-Core(Performance-core,성능 코어)
* **역할**: 게임, 영상 편집 등 무거운 작업 전담
* **하이퍼 스레딩**: 코어 1개가 마치 2개처럼 작동하여 한 번에 두가지 일을 처리하는 방식

### 2.E-Core(Effcient-core,효율 코어)
* **역할**: 인터넷 서핑, 음악 재생 등 가벼운 작업 전담
* **특징**: 1코어당 1개의 일만 하지마ㅣㄴ, 전력을 아주 적게 먹는다

## 🔢 스레드(Thread) 계산 공식
* 전체 스레드 수 = (P-Core 개수 × 2) + (E-Core 개수)

# 🌐 네트워크(Network) 및 시스템 구조 정리

## 1. 네트워크 토폴로지 (Topology, 형상)
네트워크 장치들을 물리적으로 어떻게 연결할 것인가에 대한 구조입니다.
ring -> mesh -> bus로 변해 왔다!!
| 구조명 | 핵심 특징 | 주요 장점 | 주요 단점 |
| :--- | :--- | :--- | :--- |
| **Bus (버스형)** | 중앙 공통 배선에 단말기 연결 | 설치 비용이 가장 저렴함 | 중앙선 고장 시 전체 네트워크 마비 |
| **Star (성형)** | 중앙 장치(Hub)를 통해 연결 | 관리와 확장이 매우 쉬움 | 중앙 장치 고장 시 전체 네트워크 마비 |
| **Ring (링형)** | 인접한 두 대와 고리 모양 연결 | 데이터 충돌 가능성이 낮음 | 노드 하나만 고장 나도 전체 영향 |
| **Mesh (망형)** | 모든 지점을 그물망처럼 연결 | 장애 발생 시 우회로가 있어 매우 안전함 | 설치 비용이 비싸고 관리가 복잡함 |

---

## 2. 인터넷과 프로토콜 (IP)
* **Host (호스트)**: 네트워크 망에 연결되어 서비스를 제공하거나 받는 모든 컴퓨터
* **Internetwork (인터넷)**: 여러 네트워크(Network)들이 서로 연결되어 정보를 주고받는 거대한 망
* **IP (Internetwork Protocol)**: 네트워크 간 통신을 하기 위해 약속된 공통의 규약
* **IP Address (주소)**: 네트워크 상에서 각 장치를 식별하기 위해 할당된 고유한 번호

### 🔢 IPv4 주소 체계
* **구성**: 4개의 옥텟(Octet)으로 구성 (예: 192.168.0.1)
* **크기**: 한 칸당 1Byte(8bit)씩 총 **4Byte** 체계
* **범위**: 1Byte는 0~255까지 표현 가능 
    * *따라서 이론적 최대 주소는 `255.255.255.255`입니다.* (256개 숫자 사용)

---

## 3. 이름으로 찾는 주소 (Identity)
기계는 숫자를 좋아하지만 사람은 문자를 좋아합니다.

* **Host Name (호스트 네임)**: 
    * 네트워크 내에서 개별 장치를 구별하기 위해 붙인 이름
    * 예: 내 컴퓨터 이름(`ubuntu2404`, `desktop-0000`)
* **Domain Name (도메인 네임)**: 
    * 인터넷 전체 영역에서 조직이나 서비스의 위치를 나타내는 이름
    * 예: `www.naver.com`
* **URL**: 도메인 네임을 포함하여 특정 페이지의 전체 경로를 나타내는 주소

작성하신 가상화 환경을 계층별로 정리하면 다음과 같습니다. (상단일수록 소프트웨어, 하단일수록 하드웨어)

| 계층 | 구성 요소 | 세부 내용 |
| :--- | :--- | :--- |
| **최상위 OS** | **Linux (Guest)** | Host Name: `ubuntu2404` (가상 머신 내부) |

# 🖥️ 터미널 및 웹 서비스 호스팅 정리

## 1. 터미널 (Terminal)의 개념
사용자와 컴퓨터 사이에서 명령을 전달하고 결과를 보여주는 인터페이스 장치입니다.

| 항목 | 설명 | 비유 및 특징 |
| :--- | :--- | :--- |
| **터미널** | 모니터와 키보드 한 쌍 | 사람과 컴퓨터 간의 **인터페이스(Interface)** 역할 |
| **프롬프트 (Prompt)** | 화면에 글씨가 출력되는 대기 상태 | 사용자의 명령을 받을 준비가 되었음을 알림 |
| **표기 예시** | `user@ubuntu2404:~$` | `사용자계정@호스트네임:현재위치 권한` 순으로 표시 |

---

## 2. IDC와 호스팅 (Hosting)
웹 서비스를 운영하기 위해 전문적인 장비와 네트워크 환경을 빌려 쓰는 개념입니다.

| 용어 | 핵심 정의 | 주요 목적 및 특징 |
| :--- | :--- | :--- |
| **IDC (Internet Data Center)** | 서버 기기를 수용하고 연결해주는 시설 | 서버용 건물 및 네트워크 망 임대 |
| **Web Server (Hosting)** | 웹 서비스에 특화된 PC와 네트워크 임대 | 개인이 서버를 직접 구축하는 비용과 관리 부담 절감 |
| **Hosting Service** | 웹 서버의 일정 공간을 빌려주는 서비스 | 웹 사이트 및 서비스를 외부에서 접속 가능하게 함 |

---

## 3. 웹 서비스 소프트웨어 구성 (SW Stack)
사용자가 웹 서버에 접속했을 때 동작하는 소프트웨어의 역할 분담입니다.

| 구분 | 역할 | 비유 |
| :--- | :--- | :--- |
| **프론트엔드 (Front-end)** | 사용자가 눈으로 직접 보고 클릭하는 화면 구성 | 식당의 **홀(Hall)**: 메뉴판, 인테리어, 접객 |
| **백엔드 (Back-end)** | 데이터 처리, DB 연동, 비즈니스 로직 담당 | 식당의 **주방(Kitchen)**: 요리, 식재료 관리 |

---
> 💡 **Tip:** 가상화 환경(VirtualBox)에서 리눅스를 켰을 때 나오는 검은 화면이 바로 **터미널**이며, 그 안에 떠 있는 `user@ubuntu2404:~$`가 **프롬프트**입니다.

# 🐧 리눅스(Linux) 기초 및 파일 시스템 정리

## 1. 리눅스 파일 시스템의 이해
리눅스에서는 **"모든 것이 파일이다"**라는 철학을 가집니다. 디렉토리(폴더)조차도 파일의 한 종류로 취급됩니다.

| 구분 | 설명 | 윈도우 대응 개념 |
| :--- | :--- | :--- |
| **Directory** | 파일을 저장하는 공간 (파일의 일종) | 폴더 (Folder) |
| **File** | 실제 데이터가 저장된 단위 | 파일 (File) |
| **Root ( / )** | 시스템의 최상위 디렉토리 | C드라이브 (C:\) |
| **Home ( ~ )** | 현재 로그인한 사용자의 개인 공간 | /home/user/ |

---

## 2. 기본 터미널 명령어
시스템을 제어하기 위한 시스템 소프트웨어(명령어)들입니다.

| 명령어 | 기능 | 비유/상세 |
| :--- | :--- | :--- |
| `ls` | List | 현재 위치의 파일 목록 보기 |
| `ls -l` | Long List | 권한, 날짜, 소유자 등 상세 정보 출력 |
| `cd` | Change Directory | 다른 디렉토리로 이동 |
| `mkdir` | Make Directory | 새로운 디렉토리(폴더) 생성 |
| `clear` | 화면 정리 | 터미널 창 깨끗하게 비우기 |
| `chmod` | Change Mode | 파일이나 디렉토리의 권한 변경 |
| `sudo` | Super User Do | 관리자(Root) 권한으로 명령 실행 |

---

## 3. 권한(Permission) 체계
리눅스는 보안을 위해 소유자, 그룹, 기타 사용자로 권한을 엄격히 구분합니다.



| 구분 | 기호 | 의미 | 숫자 값 |
| :--- | :---: | :--- | :---: |
| **Directory** | `d` | 파일이 아닌 디렉토리임을 표시 | - |
| **Read** | `r` | 읽기 권한 | 4 |
| **Write** | `w` | 쓰기/수정 권한 | 2 |
| **Execution** | `x` | 실행 권한 | 1 |

### 🔢 권한 합산 (예: 777)
* **rwx (7)** = 4(r) + 2(w) + 1(x)
* **d rwx rwx rwx** : 소유자(7) / 그룹(7) / 기타 사용자(7) 모두에게 모든 권한 부여

## 📝 Vi 편집기 단축키 모음집

명령 모드에서 편집을 시작하거나 다시 명령 모드로 돌아갈 때 사용합니다.

---

### 2. 명령 모드: 커서 이동
문서 내에서 빠르게 원하는 위치로 이동할 때 유용합니다.

| 단축키 | 기능 설명 | 상세 이동 |
| :--- | :--- | :--- |
| **h, j, k, l** | 좌, 하, 상, 우 이동 | 기본 방향키 역할 |
| **w / e** | 다음 단어의 처음(w) / 끝(e)으로 이동 | 단어 단위 이동 |
| **0 / ^** | 줄 맨 앞(0) / 현재 행의 처음(^)으로 이동 | - |
| **$** | 현재 행의 마지막으로 이동 | 행 끝 이동 |
| **gg / G** | 문서 맨 앞(gg) / 문서 맨 아래(G)로 이동 | 문서 전체 이동 |
| **nG** | n번째 줄로 이동 (n=숫자) | 특정 행 이동 |
| **H / M / L** | 화면의 첫 줄(H) / 중간(M) / 끝 줄(L)로 이동 | 화면 기준 이동 |
| **Ctrl + F / B** | 다음 화면(F: Page Down) / 이전 화면(B: Page Up) 이동 | 페이지 단위 이동 |

# 🛠️ 운영체제의 핵심 구조: 커널과 시스템 소프트웨어

## 1. 커널(Kernel)과 시스템 소프트웨어의 관계
운영체제라는 전체 시스템 안에서 커널은 '관리자'의 역할을, 시스템 명령어는 '도구'의 역할을 수행합니다.

| 구분 | 핵심 정의 | 상세 역할 및 자원 관리 |
| :--- | :--- | :--- |
| **커널 (Kernel)** | 운영체제의 **심장** | **자원 관리**: CPU 스케줄링, 메모리 할당, 디스크 I/O 제어 등 하드웨어 자원을 효율적으로 배분 |
| **시스템 명령어** | **시스템 소프트웨어** | **인터페이스**: 사용자가 커널에게 명령을 내릴 수 있도록 돕는 도구 세트 (예: `ls`, `cd`, `mkdir`) |

---

## 2. 운영체제 계층 구조 (Layered Architecture)
사용자가 명령어를 입력했을 때 하드웨어 자원이 관리되는 흐름입니다.

| 계층 | 구성 요소 | 설명 |
| :--- | :--- | :--- |
| **4계층** | **사용자 및 응용 프로그램** | 웹 브라우저, 게임, 텍스트 편집기(vi) 등 |
| **3계층** | **쉘(Shell) 및 명령어** | 사용자의 **시스템 명령어**를 커널이 이해할 수 있게 번역 |
| **2계층** | **커널(Kernel)** | 하드웨어를 직접 제어하고 자원을 관리하는 **운영체제의 핵심** |
| **1계층** | **하드웨어(H/W)** | CPU, RAM, SSD 등 실제 물리적 자원 |



---

## 3. 왜 '자원 관리'가 중요한가?
커널이 자원을 관리하지 않으면 다음과 같은 문제가 발생할 수 있습니다.

* **충돌 방지**: 여러 프로그램이 동시에 메모리의 같은 공간을 쓰려 할 때 이를 조율합니다.
* **공정성**: 특정 프로그램이 CPU를 독점하지 않도록 시간을 나누어 배분합니다.
* **보안**: 권한이 없는 사용자가 핵심 시스템 파일(Root 영역)에 접근하지 못하도록 차단합니다.

---
> 💡 **전공자용 한 줄 요약**
> "우리가 터미널에서 입력하는 **시스템 명령어**는 **시스템 소프트웨어**의 일종이며, 이를 통해 **커널**에 명령을 전달하여 컴퓨터의 **하드웨어 자원**을 움직이게 합니다."

## 4. 프로세스 및 자원 관리

운영체제(OS)는 컴퓨터의 물리적 부품들을 관리하고 프로세스 간의 자원 공유를 중재합니다.

| 구분 | 구성 요소 | 운영체제의 역할 |
| :--- | :--- | :--- |
| **핵심 자원** | CPU, Memory, 보조기억장치, 입출력장치 | 각 장치가 효율적으로 작동하도록 제어 |
| **자원 공유** | 프로세스 간 자원 배분 | 여러 프로세스가 충돌 없이 자원을 나누어 쓰도록 관리 |

> **💡 핵심 요약**
> PC 하드웨어 위에는 운영체제가 존재하며, 운영체제는 프로세스가 자원을 사용하는 모든 과정을 관리합니다.

프로그램이 실행되기 위해 메모리에 로드되는 과정과 관련된 개념입니다.

| 항목 | 설명 | 특징 |
| :--- | :--- | :--- |
| **프로그램** | 보조기억장치에 저장된 실행 코드 | 수동적인 상태의 데이터 덩어리 |
| **프로세스** | 메모리에 업로드되어 실행 중인 프로그램 | 능동적으로 자원을 사용하는 주체 |
| **실행 원리** | **폰노이만 아키텍처** | 프로그램이 메모리에 내장되어야만 실행 가능한 방식 |

* **프로세스 상태**: 생성 → 준비 → (Dispatch) → 실행 → 종료/대기
  
* **구조**: `프로그램(ps)` + `인자(-ef)`
* **실행 예시**: `ps -ef`
    * **Program**: `ps`
    * **Argument**: `-ef`
    * **PPID**: `bash` (부모 프로세스)
* **인자 전달 예시**: `./test option` 실행 시
    * 프로그램 이름(`./test`)과 옵션(`option`) 등 총 **2개**의 인자가 전달됨

# 🌐 네트워크(Network) 핵심 이론 정리

## 1. 통신의 설계도: OSI 7 계층 & 계층형 아키텍처
네트워크는 복잡한 통신 과정을 효율적으로 관리하기 위해 '층(Layer)'을 나누어 설계되었습니다.

### 🏗️ OSI 7 계층의 본질
* **개념적 설계도**: 표준 규격이라기보다 "데이터 전달을 위해 꼭 거쳐야 하는 철학적 가이드라인"입니다.
* **TCP/IP 모델**: 실제 인터넷에서 사용하는 실전 모델이며, OSI 계층은 이를 이해하기 위한 이론적 토대입니다.

| 계층 (Layer) | 핵심 역할 및 비유 |
| :--- | :--- |
| **7. Application** | 사용자 인터페이스 (HTTP 등 응용 서비스) |
| **6. Presentation** | 데이터 형식 변환, 암호화, 압축 (**HTML** 등) |
| **5. Session** | 통신 세션 유지 및 관리 (연결성 유지) |
| **4. Transport** | 데이터 전송 방식 결정 (TCP/UDP) |
| **3. Network** | 망 구성 및 최적의 경로 선택 (IP, 라우팅) |
| **2. Data Link** | 물리적 신호에 주소(MAC)와 순서를 부여하여 혼선 방지 |
| **1. Physical** | 도로(매체)를 깔고 운송 수단(신호)을 정하는 계층 |

### 🛠️ 계층형 아키텍처(Layered Architecture)의 이점
* **관심사의 분리**: 각 층은 맡은 역할에만 집중합니다.
* **유지보수 용이성**: 랜선을 바꾼다고 해서 메시지 내용이 변하지 않는 것과 같습니다.
* **독립적 개발**: 인터페이스(약속)만 있다면 UI와 DB 로직을 따로 개발할 수 있습니다.
* **재사용성**: 한 번 만든 비즈니스 로직(예: 성적 계산)을 웹과 모바일에서 공통 사용 가능합니다.

---

## 2. 운영체제(OS)와 하드웨어의 연결 구조

### 1. 주요 구성 요소
* **IP 프로토콜 스택**: OS 내부의 통신 규약 집합체. 데이터 패킷화 및 경로(IP) 결정 담당.
* **네트워크 드라이버**: OS의 명령을 하드웨어(NIC) 언어로 번역하는 통역사 소프트웨어.
* **NIC (랜카드)**: 디지털 데이터를 전기/전파 신호로 변환하여 물리적으로 송수신하는 장치.

### 2. 계층 간 상호작용
1. **OS 영역**: 데이터를 만들고 IP 주소를 붙임 (논리적 처리)
2. **드라이버 영역**: 하드웨어가 이해할 수 있는 명령어로 변환 (중재)
3. **하드웨어 영역**: 실제 케이블이나 전파를 통해 신호 전송 (물리적 처리)

> **핵심**: "네트워크 드라이버는 소프트웨어가 하드웨어를 부려먹을 수 있게 해주는 도구이며, 이 모든 것이 계층(Layer) 구조로 설계되어 있어 부품이 바뀌어도 전체 통신 시스템이 무너지지 않는다."

[애플리케이션 → OS(커널) → 드라이버 → 하드웨어] 

---

## 3. 전파와 주파수 (무선 통신의 원리)
물리적인 신호가 데이터를 실어 나르는 방식입니다.

### 📡 주파수와 전송량
* **단위 (Hz)**: 주파수가 높을수록 더 많은 정보(bit)를 담을 수 있습니다.
* **직진성**: 주파수가 높아질수록 직진성이 강해집니다 (위성 통신 등).
* **단위 체계**: 10^3(Kilo), 10^6(Mega), 10^9(Giga), 10^12(Tera)

### 🗼 통신 방식의 구분
* **LOS (Line of Sight)**: 송수신기가 마주 보고 있어야 함 (고주파 핵심).
* **NLOS (Non-Line of Sight)**: 장애물로 보이지 않는 상태. 저주파는 가능하나 고주파는 기지국을 촘촘히 세워야 함.
* **GPS**: 10개의 전파 중 4개만 잡혀도 위치 특정이 가능합니다.

### 🔓 대역별 특징 (ISM vs 면허 대역)
| 구분 | ISM Band (2.4GHz) | 면허 대역 (3G, 4G, 5G) |
| :--- | :--- | :--- |
| **비유** | 누구나 무료로 쓰는 **공원** | 임대료를 내고 쓰는 **사유지** |
| **대표 주자** | Wi-Fi, 블루투스, 무선마우스 | 통신사(SKT, KT, LGU+) 대역 |
| **특징** | 혼선 가능성 있음, 무료 | 독점권 보장, 품질 일정, 전파법 보호 |

---

## 4. 데이터의 이동 통로 (RAN & 광통신)
1. **RAN (무선 접속망)**: 스마트폰이 가장 먼저 만나는 기지국 구간 (무선 연결).
2. **광통신**: RAN에서 받은 데이터를 전 세계로 실어 나르는 빛의 고속도로.
3. **흐름**: 서버 → 광통신망(빛) → RAN(기지국) → 스마트폰(전파).

---

## 5. 유선 통신의 과학: UTP 케이블
우리가 쓰는 랜선(Twisted Pair)에 숨겨진 물리 법칙입니다.

* **전자기 유도**: 전기가 흐르면 자기장이 생겨 간섭(노이즈)이 발생합니다.
* **차동 신호 (꼬임의 기술)**:
    * A선(+)과 B선(-)에 역신호를 보내 발생한 자기장을 서로 **상쇄(Cancel out)**시킵니다.
    * 선을 꼬아두면 외부 노이즈가 두 선에 균일하게 섞여 제거하기 쉬워집니다.
* **결과**: 신호 무결성이 확보되어 고속 통신과 높은 주파수 유지가 가능해집니다.

# 🔌 OSI 1계층: 물리 계층 (Physical Layer)

> **"데이터라는 손님을 태우고 달릴 도로(매체)를 깔고, 그 도로에 맞는 운송 수단(신호)을 정하는 계층"**

물리 계층은 복잡한 데이터(0과 1)를 상대방에게 전달하기 위해 **어떤 물리적인 매체(길)**를 사용할 것인지, 그리고 그 길에 데이터를 어떤 신호로 흘려보낼 것인지를 결정합니다.

---

## 1. 연결의 본질: "일단 이어져야 한다"
눈에 보이든 안 보이든, 두 장치 사이에는 에너지가 흐를 수 있는 통로가 반드시 존재해야 합니다.

| 구분 | 연결 방식 | 예시 |
| :--- | :--- | :--- |
| **유선 (Wired)** | 눈에 보이는 연결 | 구리선(랜선), 광케이블 등 |
| **무선 (Wireless)** | 눈에 보이지 않는 연결 | 전파(Wi-Fi, LTE, 5G), 적외선 등 |

---

## 2. 주요 연구 및 규격 대상
물리 계층은 단순히 연결 상태를 넘어 다음과 같은 물리적 약속(규격)을 정의합니다.

### 🛤️ 매체 (Media)
* 데이터를 실어 나를 물리적 경로를 선택합니다.
* **종류**: 구리선(전기), 광섬유(빛), 공기(전파)

### 📡 신호 (Signal)
* `0`과 `1`이라는 디지털 데이터를 어떤 물리적 에너지로 바꿀지 결정합니다.
* **변환 방식**: 전압(V)의 높낮이, 빛의 깜빡임, 전파의 주파수 변화 등

### 🛠️ 커넥터와 장치
* **커넥터**: 랜선 끝 잭(RJ-45)의 모양, 케이블의 굵기 등 물리적 규격
* **네트워크 장비**: 신호를 증폭하거나 전달하는 **허브(Hub)**, **리피터(Repeater)**

---
> 💡 **요약**: 비트(Bit) 단위의 데이터를 전기적, 광학적 신호로 변환하여 물리적 매체를 통해 송수신하는 가장 기초적인 단계입니다.

# 🔗 OSI 2계층: 데이터 링크 계층 (Data Link Layer)

> **"인접한 장치 간에 신뢰성 있는 데이터를 전달하는 규칙"**

1계층에서 전압 신호를 보낼 준비가 되었다면, 2계층은 그 신호를 **'의미 있는 데이터(Frame)'**로 묶고 관리하는 역할을 수행합니다.

---

## 1. 통신 환경에 따른 역할
전선(매체)의 연결 상태에 따라 해결해야 하는 문제가 달라집니다.

| 구분 | 통신 방식 | 주요 작업 및 역할 |
| :--- | :--- | :--- |
| **1:1 연결** | Point-to-Point | **동기화**: 약속된 속도(bps)로 전압 송수신<br>**프레이밍(Framing)**: 전압 신호를 데이터 묶음 단위로 끊어서 읽기 |
| **다대다 연결** | Multi-Access | **주소 판별**: MAC 주소를 통해 수신자 식별<br>**충돌 방지(MAC)**: 데이터 신호가 뭉개지지 않도록 교통정리<br>**에러 검출**: 전송 중 데이터 파손 여부 체크 |

---

## 2. 핵심 장비 및 인터페이스

### 🧱 핵심 장비: 스위치 (Switch)
* **역할**: 여러 개의 전선이 모이는 곳에서 데이터를 정확한 목적지로 전달합니다.
* **원리**: 각 장비의 **MAC 주소**를 기억하고 있다가, 데이터가 들어오면 해당 컴퓨터가 연결된 선으로만 데이터를 쏴줍니다.

### 💳 NIC (랜카드 / 이더넷 어댑터)
본체에 박혀 있는 이 장치는 **1계층(물리)과 2계층(데이터 링크)** 사이의 다리 역할을 합니다.
* **물리적 주소(MAC Address)**: 칩 제조 시 할당되는 48비트의 고유 번호(주민등록번호).
* **신호 변환**: OS의 디지털 데이터를 전압 신호로 바꾸거나, 반대로 전압 신호를 0과 1로 해석합니다.
* **용어 정리**: **NIC** = **이더넷 어댑터** = **물리적 인터페이스** (관점에 따라 이름만 다름).

---

## 3. 계층별 상호작용 흐름
데이터가 하드웨어에서 소프트웨어로 전달되는 과정입니다.

1.  **물리적 구리선 (1계층)**: 전기 신호(전압)가 흐르는 통로.
2.  **NIC / 어댑터 (1~2계층)**: 
    * (1계층): 전압을 0과 1로 해석.
    * (2계층): 데이터 덩어리에서 **MAC 주소**를 확인하여 내 것인지 판단.
3.  **네트워크 드라이버 (SW)**: OS가 NIC 하드웨어를 제어할 수 있게 돕는 **통역사**.
4.  **IP 프로토콜 스택 (3계층 이상)**: 드라이버를 통해 올라온 데이터를 인터넷 데이터로 처리.

---

## 4. 주요 표준 규격 (IEEE 802)
| 규격 번호 | 명칭 | 관장 범위 |
| :---: | :--- | :--- |
| **IEEE 802.3** | **이더넷 (Ethernet)** | 유선 LAN의 하드웨어 규격 및 충돌 방지 규칙 |
| **IEEE 802.11** | **와이파이 (Wi-Fi)** | 무선 근거리 통신망(WLAN) 규격 |

> 💡 **핵심 포인트**
> 2계층까지는 '네트워크'가 없습니다. 오직 케이블 상에서 정보를 어떻게 주고받을지에 대한 **'매체 접근 제어(MAC)'** 규칙만 존재합니다.


# 🌐 네트워크 3계층(IP) & 4계층(TCP/UDP) 마스터 정리

## 1. 네트워크 3계층: 전 세계를 잇는 논리적 주소 (IP)
유선(PC), 무선(노트북) 등 매체에 상관없이 동일한 IP 프로토콜을 사용하는 이유는 **7계층 레이어 구조** 덕분입니다. 계층 간 결합도가 낮아 어떤 환경에서도 무너지지 않는 유연한 통신이 가능합니다.

### 🏢 주소 체계의 아키텍처 (위계 구조)
IPv4 클래스 체계는 우리가 사는 주소 시스템과 유사합니다.

| 구분 | 개념 | 비유 |
| :--- | :--- | :--- |
| **Network ID** | 네트워크 주소 | 아파트 단지 이름 (예: 서울시 OO구 XX아파트) |
| **Host ID** | 호스트 주소 | 해당 아파트의 동/호수 (예: 101동 502호) |
| **Routing** | 길 찾기 | 체계적인 주소 시스템을 바탕으로 목적지까지 경로를 찾는 과정 |

### 📊 IPv4 클래스(Class) 체계
기관의 규모에 따라 주소를 효율적으로 나누어 사용합니다.

| 클래스 | 최상위 비트 | 범위 | 서브넷 마스크 | 할당 가능 IP 개수 |
| :---: | :---: | :--- | :--- | :--- |
| **A** | `0` | 0.x.x.x ~ 127.x.x.x | 255.0.0.0 (/8) | 약 1,600만 개 (국가/대기업) |
| **B** | `10` | 128.x.x.x ~ 191.x.x.x | 255.255.0.0 (/16) | 약 65,000 개 (대학/중견기업) |
| **C** | `110` | 192.x.x.x ~ 223.x.x.x | 255.255.255.0 (/24) | 254개 (소규모/가정) |

> 💡 **주의**: 호스트 주소 중 `.0`(네트워크 이름)과 `.255`(브로드캐스트/방송용)는 사용자가 쓸 수 없으므로 실제 사용 가능한 IP는 전체 개수에서 **2를 뺀 값**입니다.

---

## 2. 서브넷 마스크(Subnet Mask)와 서브넷팅
IP 주소는 원래 전 세계에 소리를 지르는 방식(Bus 방식)이지만, **서브넷 마스크**라는 "울타리"를 통해 네트워크를 효율적으로 격리합니다.

### ✂️ 서브넷팅 계산 (예시 기반)
네트워크 마스크는 2진수로 보았을 때 연속된 1의 개수입니다.

| 목표 수용 인원 | 서브넷 마스크 (10진수) | CIDR 표기 | 할당 가능 IP 범위 |
| :--- | :--- | :--- | :--- |
| **15명 수용** | 255.255.255.240 | **/28** | 16개 단위 (0~15, 16~31...) |
| **127명 수용** | 255.255.255.128 | **/25** | 128개 단위 (0~127, 128~255) |

### 🛠️ CIDR (Classless Inter-Domain Routing)
* **낭비 방지**: 클래스 단위로만 팔지 않고 "원하는 만큼만 잘라서 파는" 방식입니다.
* **유연성**: 500개가 필요하면 B클래스 전체 대신 `/23`(512개)을 할당하여 자원을 아낍니다.

---

## 3. 네트워크 4계층: 프로세스 식별과 전송 (Transport)
IP 주소가 '집 주소'라면, **포트(Port)**는 그 집 안에 있는 여러 프로그램 중 누구와 대화할지 결정하는 '방 번호'입니다.

### 🚪 포트(Port)의 역할
* **상황**: 컴퓨터 1대에 카카오톡, 웹 브라우저 등 여러 프로그램이 동시에 통신함.
* **해결**: IP 주소 뒤에 포트 번호를 표기하여 식별합니다. (예: `172.35.50.100:8080`)
* **L4 스위치**: IP와 Port를 모두 확인하여 여러 서버로 트래픽을 나누어 주는 **로드 밸런싱**을 수행합니다.

### 🏎️ TCP vs UDP 핵심 비교
| 구분 | TCP (신뢰의 트럭) | UDP (속도의 오토바이) |
| :--- | :--- | :--- |
| **특징** | 연결 지향 (3-way Handshake) | 비연결형 (냅다 던짐) |
| **신뢰성** | 매우 높음 (분실 시 재전송) | 낮음 (분실해도 그냥 진행) |
| **속도** | 상대적으로 느림 (확인 절차) | 매우 빠름 (가벼움) |
| **주요 용도** | 이메일, 웹서핑(HTTP), 파일전송 | 스트리밍, 온라인 게임, 보이스톡 |

---

## 4. 공유기의 마법 (NAT & DHCP)
공유기는 사설 IP 대역을 관리하며 외부 인터넷과의 가교 역할을 합니다.

| 기술 | 풀네임 | 역할 | 비유 |
| :--- | :--- | :--- | :--- |
| **NAT** | Network Address Translation | 사설 IP를 대표 공인 IP로 변환 | "밖에 나갈 땐 내 이름을 빌려줄게!" |
| **DHCP** | Dynamic Host Config Protocol | 네트워크 주소를 자동으로 할당 | "자리가 났으니 이 번호를 쓰렴!" |


# 🔗 OSI 5계층: 세션(Session)의 이해

## 1. 웹 통신의 특징 (Stateless)
* **비연결성**: 웹페이지 전송 후 서버와 브라우저의 연결은 즉시 끊어짐.
* **한계**: 페이지 이동 시마다 재연결이 필요하며, 서버는 사용자가 누구인지 기억하지 못함.

## 2. 세션(Session)의 역할
서버와 클라이언트 간의 **연결성(Stateful)**을 유지하기 위해 사용됩니다.

| 구분 | 상세 내용 |
| :--- | :--- |
| **핵심 개념** | 서버가 클라이언트를 식별하기 위한 논리적 연결 통로 |
| **세션 ID** | 서버가 발급한 일종의 **'통행증'**. 브라우저는 매 요청마다 이를 제시함 |
| **마법의 원리** | 실제로는 연결이 끊기지만, ID를 통해 서버가 사용자를 기억하게 하여 연결된 것처럼 처리 |

## 3. 요약
> "웹 브라우저와 서버는 통신 직후 남남이 되지만, 서버가 발급한 **세션 ID**를 브라우저가 지속적으로 제시함으로써 마치 계속 연결되어 있는 것처럼 속이는 기술이 바로 **세션**이다."


# 🎨 OSI 6계층: 표현 계층과 마크업 언어(ML)

## 1. 용어 정리
* **HT (Hyper Text)**: 문서 간의 연결성을 가진 텍스트.
* **ML (Markup Language)**: 문서의 구조와 속성을 정의하는 언어.
* **HTML**: 웹 문서를 작성하기 위한 표준 마크업 언어.

## 2. 마크업의 원리: 글자에 능력 부여하기
단순한 텍스트에 태그를 입혀 특수한 속성을 부여하는 것을 의미합니다.
* **예시**: `Berkly`라는 글자에 링크 속성을 부여하여 특정 IP(`172.36.7.128`)로 연결되게 함.

# 🧠 인공지능 및 딥러닝 핵심 개념 정리

## 1. 개요 및 라이브러리
* **주요 라이브러리**
    * `sklearn`: 기본적인 머신러닝 알고리즘 (Decision Tree, Random Forest 등)
    * `tensorflow` / `pytorch`: 딥러닝 프레임워크 (신경망 구현)
    * `transformers`: 사전 학습된 모델(LLM 등) 활용 라이브러리
* **산업 배경**: 반도체 산업(트랜지스터 생성)의 발전이 연산 능력을 제공하며 인공지능(머신러닝) 구현이 시작됨.

---

## 2. 머신러닝의 기초
* **지능**: 학습을 통해 판단하고 예측하는 능력을 갖게 함.
* **알고리즘 예시**:
    * **Decision Tree**: 질문을 Yes/No로 나누어 의사결정을 내리는 방식.
    * **Random Forest**: 여러 개의 의사결정 나무가 모인 '숲' 형태의 알고리즘.

---

## 3. 신경세포의 수학적 모델: 퍼셉트론 (Perceptron)
뇌의 신경세포(Neuron) 동작 원리를 모델링한 딥러닝의 가장 작은 단위입니다.


### 3.1 동작 원리
1. **입력($x$)**: 외부에서 느끼는 신호.
2. **가중치($w$)**: 각 신호에 부여되는 중요도.
3. **편향($b$)**: 고정되는 값을 더해 학습 속도와 유연성에 영향을 줌.
4. **활성 함수(Activation Function)**: 출력값을 특정 범위로 제한하여 비선형 특성을 부여.

### 3.2 수식 모델링
* **기본 수식**: $y = w_1x_1 + w_2x_2 + ... + w_nx_n + b$
* **행렬(Matrix) 표현**: $y = \mathbf{W}\mathbf{X} + b$
    * 입력을 벡터(Vector) 집합으로 처리하여 행렬 곱으로 연산.
    * 행렬 곱이 안 맞을 경우 **전치(Transpose)**를 사용해 형태를 맞춤.

---

## 4. 비선형 활성 함수 (Activation Function)
단순한 직선($y=ax+b$) 형태는 예측에 한계가 있어, 비선형 함수를 통해 복잡한 데이터를 처리합니다.

* **Sigmoid**: 출력을 $0$ ~ $1$ 사이로 제한. 입력이 무한대로 가면 1, -무한대로 가면 0에 수렴.
* **ReLU (Rectified Linear Unit)**: $0$보다 작으면 $0$, $0$보다 크면 입력값 그대로 출력. 현재 가장 많이 사용됨.

---

## 5. 벡터(Vector)와 공간의 이해
* **벡터**: 데이터의 집합이며 크기와 방향을 가짐.
* **기저 벡터(Basis Vector)**: 기준이 되는 크기 1의 벡터.
* **유사성**: 두 벡터 사이의 각도가 작을수록 유사성이 높다고 판단함. (벡터 공간에서의 거리와 각도 활용)

---

## 6. 학습과 최적화 (Optimization) ⭐️
데이터($x, y$)가 있는 상황에서 최적의 $w, b$를 구하는 과정입니다.

### 6.1 손실 함수 (Loss Function)
* **Error(Loss)**: 실제 정답($y$)과 예측값($\hat{y}$)의 차이.
* **MSE (Mean Squared Error)**: 오차의 부호를 없애기 위해 제곱을 하여 평균을 낸 값.

### 6.2 경사 하강법 (Gradient Descent)
손실을 최소화하기 위해 기울기(Gradient)를 이용해 가중치를 업데이트합니다.


* **핵심 원리**:
    * 기울기 > 0: 가중치($w$)를 **감소**시켜 Loss 감소.
    * 기울기 < 0: 가중치($w$)를 **증가**시켜 Loss 감소.
* **목표**: 기울기가 **0**이 되는 지점(Loss가 최소가 되는 지점)을 찾는 것.
