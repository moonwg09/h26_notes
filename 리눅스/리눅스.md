계층형 아키텍처 (Layered Architecture)

"복잡한 소프트웨어를 역할에 따라 층(Layer)으로 쪼개서 쌓는 설계 방식"

소프트웨어 내부에서도 사용자 요청이 각 층을 통과하며 처리된다.

"최상위 단에서의 설계"가 중요한 이유는 바로 '관심사의 분리'

유지보수의 용이성: 마치 랜선을 바꾼다고 해서 카카오톡 메시지 내용이 변하지 않는 것과 같습니다.

독립적인 개발:  "나는 화면(UI)만 만들 테니, 너는 데이터베이스(DB) 로직만 짜줘"가 가능해집니다. 각 층 사이에는 '약속(Interface)'만 있으면 되니까요.

재사용성:  비즈니스 로직 층에서 만든 "성적 계산 알고리즘"은 웹 앱에서도 쓰고, 모바일 앱에서도 그대로 가져다 쓸 수 있습니다.

극초단파(2.4ghz) : 블루투스, wifi

ISM Band: "공유지와 같은 무료 전파 대역"

대표 주자 2.4GHz: 우리가 쓰는 Wi-Fi, 블루투스, 무선 마우스, 전자레인지가 모두 이 대역을 씁니다.

면허 대역 (3G, 4G, 5G): "임대료를 내고 쓰는 사유지"
통신사(SKT, KT, LGU+)가 쓰는 대역은 ISM Band와 완전히 다릅니다.

독점권: 정부로부터 천문학적인 비용(경매)을 지불하고 특정 기간 동안 특정 대역을 독점적으로 쓸 권리를 삽니다.

허가의 영역: 허가받지 않은 사람이 이 대역을 쓰면 전파법 위반입니다.

품질 보장: 주인(통신사)이 관리하는 도로이므로 ISM Band처럼 혼선이 생기지 않고 통신 품질이 일정합니다.

"ISM Band(2.4GHz)는 누구나 무료로 쓰는 공원이고, 3G/5G 대역은 통신사가 비싼 임대료를 내고 빌려 쓰는 유료 고속도로다.


주파수가 높아질 수록 직진성이 강해진다(위성 통신 등)

gps : 10개의 선(전파) 중 4개만 잡혀도 위치를 특정할 수 있다.

RAN (Radio Access Network, 무선 접속망)
"내 스마트폰이 가장 먼저 만나는 네트워크의 끝단"
스마트폰과 기지국 사이의 무선 연결을 담당하는 구간입니다.

광통신 (Optical Fiber Communication)
"RAN에서 받은 데이터를 전 세계로 실어 나르는 초고속 고속도로"

유튜브 서버 → 광통신망: 미국이나 한국 데이터센터에서 빛의 속도로 이동.

광통신망 → RAN (기지국): 동네 기지국까지 광케이블을 타고 데이터가 도착.

RAN → 스마트폰: 기지국 안테나가 이 데이터를 다시 **전파(무선)**로 바꿔서 내 폰에 쏴줌.



전자기 유도 현상: "전기가 흐르면 자기장이 생긴다"

UTP 케이블: 꼬임의 과학 (Twisted Pair)
우리가 흔히 쓰는 랜선 안을 보면 8가닥의 선이 두 가닥씩 짝을 지어 4세트로 꼬여 있다

차동 신호
A선: + 신호 전송

B선: - 신호(역신호) 전송

결과: 두 선에서 발생하는 자기장의 방향이 정반대가 되어 서로를 **상쇄(Cancel out)**시킵니다. 내부에서 발생하는 간섭을 스스로 잡아먹는 셈이죠.

선을 꼬아두면 외부에서 노이즈가 들어올 때, 두 선에 동일한 양의 노이즈가 골고루 섞이게 됩니다.

신호의 무결성: 자기장 간섭과 외부 노이즈가 제거되니, 아주 미세한 신호도 끝까지 살아남습니다.

속도 유지: 신호가 깨지지 않으니 다시 보낼 일이 줄어들고, 더 높은 주파수(데이터)를 실어 보낼 수 있습니다.



1계층: 물리 계층 (Physical Layer)
"데이터를 전기 신호로 바꿔서 물리적으로 실어 나르는 통로"

물리 계층은 복잡한 데이터(0과 1)를 상대방에게 전달하기 위해 **어떤 물리적인 매체(길)**를 사용할 것인지, 그리고 그 길에 데이터를 어떤 신호로 흘려보낼 것인지를 결정하는 곳입니다.

1. 연결의 본질: "일단 이어져야 한다"
눈에 보이든 안 보이든, 두 장치 사이에는 에너지가 흐를 수 있는 통로가 있어야 합니다.

유선 (눈에 보이는 연결): 구리선(랜선), 광케이블 등

무선 (눈에 보이지 않는 연결): 전파(Wi-Fi, LTE, 5G), 적외선 등

2. 주요 연구 및 규격 대상
단순히 "연결만 하면 끝"이 아니라, 아래와 같은 물리적 약속을 정의합니다.

매체(Media): 구리선으로 보낼까? 빛(광섬유)으로 보낼까? 아니면 공기 중으로 쏠까?

신호(Signal): 0과 1이라는 디지털 데이터를 **전압(V)**으로 바꿀지, 빛의 깜빡임으로 바꿀지, 전파의 주파수로 바꿀지 결정합니다.

커넥터와 장치: 랜선 끝에 달린 잭(RJ-45)의 모양, 케이블의 굵기, 신호를 증폭해 주는 **허브(Hub)**나 리피터(Repeater) 같은 장비들이 여기에 속합니다.

"데이터라는 손님을 태우고 달릴 도로(매체)를 깔고, 그 도로에 맞는 운송 수단(신호)을 정하는 계층"


2계층: 데이터 링크 계층 (Data Link Layer)
"인접한 장치 간에 신뢰성 있는 데이터를 전달하는 규칙"

1계층에서 전압을 높이고 낮추며 신호를 보낼 준비가 되었다면, 2계층은 그 신호를 '의미 있는 데이터'로 묶고 관리하는 역할을 합니다.

1. 전선이 하나일 때 (Point-to-Point)
말씀하신 것처럼 전선이 1대 1로만 연결되어 있다면 사실 아주 단순합니다.

동기화: "지금부터 데이터를 보낸다!"라는 신호와 함께 약속된 속도(bps)로 전압을 흘리면 됩니다.

프레이밍(Framing): 흐물흐물 흐르는 전압 신호를 어디서부터 어디까지가 '하나의 데이터 묶음'인지 끊어서 읽는 작업입니다.

2. 여러 개의 전선/장치를 사용할 때 (Multi-Access)
여기서부터 2계층의 진정한 능력이 발휘됩니다. 전선이 여러 개거나, 하나의 선에 여러 컴퓨터가 물려 있다면 다음의 문제들을 해결해야 합니다.

주소 판별 (MAC 주소): "이 데이터는 1번 전선(컴퓨터) 거니, 아니면 2번 거니?"를 구분하기 위해 각 장비의 고유 번호인 MAC 주소를 사용합니다.

충돌 방지 (Media Access Control): 여러 컴퓨터가 동시에 전압을 흘리면 신호가 뭉개지겠죠? "지금 선이 비어있나?" 확인하고 순서를 정해서 보내는 교통정리 역할을 합니다.

에러 검출: 전송 중에 전압이 튀어서 데이터가 깨지지는 않았는지 마지막에 체크합니다.

핵심 장비: 스위치 (Switch)
여러 개의 전선이 모이는 곳에는 보통 **'스위치'**라는 장비가 있습니다.

스위치는 2계층 주소인 MAC 주소를 기억하고 있습니다.

데이터가 들어오면 "아, 이건 3번 전선에 연결된 컴퓨터로 가는 거네!"라고 판단해서 정확한 길로만 데이터를 쏴줍니다.


2계층은 네트워크는 없다
케이블에서 정보 송수신을 어떻게 할지만 정한다 (1,2계층)



NIC (Network Interface Card, 랜카드)
본체 메인보드에 박혀 있거나 꽂혀 있는 이 장치는 **2계층(데이터 링크)**과 1계층(물리) 사이의 다리 역할을 합니다.

고유 번호(MAC 주소): 전 세계에서 유일한 이 카드의 주민등록번호가 저장되어 있습니다.
신호 변환: 운영체제의 IP 프로토콜 스택에서 내려온 디지털 데이터를, UTP 케이블에 흐를 수 있는 전압 신호로 변환합니다.

OS는 이 '어댑터'를 통해 네트워크 기능을 제어합니다.

결국 NIC = 이더넷 어댑터 = 물리적 인터페이스는 모두 같은 대상을 가리키지만, 하드웨어로 보느냐, OS의 관리 대상으로 보느냐, 통로로 보느냐에 따라 이름만 조금씩 다르게 부르는 것입니다.

물리적 구리선 (1계층): 전압 신호가 흐르는 통로.

NIC / 이더넷 어댑터 (1~2계층): * (1계층 역할): 전압 신호를 받아 0과 1로 해석함.

(2계층 역할): 0과 1의 덩어리에서 MAC 주소를 확인하여 내 것인지 판단함.

IP 프로토콜 스택 (3계층 이상): 드라이버를 통해 올라온 데이터를 보고 "아, 이건 인터넷 데이터구나"라고 처리함.

클래스(Class) 체계: 주소의 등급 나누기
기관의 규모에 따라 필요한 주소의 개수가 다르기 때문에, 앞부분의 숫자를 보고 "이 주소는 대형 기관용이다, 소형 기관용이다"를 구분하게 만들었습니다.

A 클래스 (대규모 기관)
범위: 0.x.x.x ~ 127.x.x.x
특징: 첫 번째 덩어리만 네트워크 주소로 쓰고, 나머지 세 덩어리(24비트)를 모두 컴퓨터(호스트) 할당에 씁니다.
개수: 한 네트워크당 약 1,600만 개의 주소를 가질 수 있습니다. (국가나 대기업 수준)

B 클래스 (중규모 기관)
범위: 128.x.x.x ~ 191.x.x.x
특징: 앞의 두 덩어리를 네트워크 주소로 씁니다.
개수: 한 네트워크당 약 65,000개의 주소를 가질 수 있습니다. (대기업, 대학 등)

C 클래스 (소규모 기관)
범위: 192.x.x.x ~ 223.x.x.x
특징: 앞의 세 덩어리를 네트워크 주소로 씁니다. 우리가 흔히 보는 공유기 주소(192.168.x.x)가 이 대역에 속합니다.
개수: 한 네트워크당 254개의 주소를 가질 수 있습니다. (소규모 사무실, 가정 등)



주소 체계 = 아키텍처 (위계 구조)
IPv4 클래스 체계는 우리가 사는 주소 시스템과 똑같습니다.
Network ID (네트워크 주소): 아파트 단지 이름 (예: 서울시 OO구 XX아파트)
Host ID (호스트 주소): 그 아파트의 동/호수 (예: 101동 502호)
클래스(A, B, C)에 따라 이 '아파트 단지 이름'의 길이를 조절하는 것이죠.
A 클래스: 큰 국가나 거대 기업용 (단지 이름은 짧고, 내부에 호수가 엄청나게 많음)
C 클래스: 작은 사무실용 (단지 이름은 상세하고, 내부에 호수는 몇 개 없음)

최상위 비트가 10이면 b class 128.0.0.0 ~ 191.255.255.255 서브넷마스크 255.255.0.0/16
최상위 비트가 110이면 c class 192.0.0.0 ~ 223.255.255.255 서브넷마스크 255.255.255.0/24

ip는 프로토콜은 버스방식을 사용한다 패킷을 하나 프로토콜을 치면 그 패킷은 네트워크에 전부다 돌아다닌다
차단하는 기준은 네트워크 마스크이다 

서브넷 마스크 
컴퓨터가 여러 대가 있는데 우리끼리만 통신을 하고 싶으면 서브넷팅을 해주면 된다
=> 서브넷 마스크 
마지막에 있는 번호로만 호스트가 식별이된다

1. 서브넷 마스크: 네트워크의 "울타리"IP 주소는 원래 전 세계에 소리를 지르는 방식(Bus 방식)입니다. 
=> 모든 패킷이 전 세계로 퍼지면 네트워크는 마비된다 
이때 서브넷 마스크가 "여기까지만 우리 동네니까 여기서만 돌아다녀!"라고 차단막을 쳐줍니다.

역할: IP 주소에서 어디까지가 **네트워크 이름(동네)**이고, 어디서부터가 **호스트(개인 번호)**인지 결정합니다.

원리: 서브넷 마스크의 1의 개수가 늘어날수록 울타리는 촘촘해지고, 그 안에 살 수 있는 호스트(컴퓨터)의 개수는 줄어듭니다.📏 

2. 서브넷팅 계산 (사용자님의 예시 기반)네트워크 마스크는 2진수로 보았을 때 연속된 1의 개수입니다.
Case A: 16대씩 묶고 싶을 때 (15명 수용)15명을 수용하려면 주소가 16개(0~15) 필요합니다. 16은 $2^4$이므로 뒤에서 4비트를 호스트용으로 남겨둡니다.
서브넷 마스크: 11111111.11111111.11111111.11110000
10진수 표기: 255.255.255.240
CIDR 표기: /28 (앞에서부터 1이 28개)
결과: 이 울타리 안에서는 0번부터 15번까지만 서로 "우리 팀"이라고 인식합니다.

Case B: 128대씩 묶고 싶을 때128은 $2^7$이므로 뒤에서 7비트를 남깁니다.
서브넷 마스크: 11111111.11111111.11111111.10000000
10진수 표기: 255.255.255.128
CIDR 표기: /25 (앞에서부터 1이 25개)
결과: 거대한 C 클래스(256개)를 딱 절반으로 쪼개서 두 개의 동네를 만듭니다.

현재방에는 15명이고 옆방에 15명이 있다

15명은 4비트만 있으면 되다 
서브넷 마스크를 255.255.255.240 /28 해주면 된다

255.255.255.128 /25  => 1일 25개
서브넷 마스크는 1의 개수

3. 한눈에 보는 서브넷 마스크 일람표
CIDR서브넷 마스크1의 개수 (2진수 마지막 옥텟)할당 가능한 IP 개수용도 
예시/24255.255.255.000000000256개일반적인 C 클래스 전체/25255.255.255.1281000000128개네트워크를 2등분 할 때/26255.255.255.1921100000064개네트워크를 4등분 할 때/27255.255.255.2241110000032개소규모 팀 (약 30명)/28255.255.255.2401111000016개사용자님 예시 (15명)

4. 서브넷팅의 이유

1. 브로드캐스트 도메인 분리: 256명이 한꺼번에 소리 지르는 것보다, 16명씩 나눠서 소리 지르는 게 훨씬 조용하고 효율적입니다.
2. 보안: 옆방(다른 서브넷) 사람이 우리 방의 패킷을 함부로 엿듣지 못하게 격리합니다.
3. 관리 효율: "1번방은 개발팀, 2번방은 인사팀" 식으로 IP 대역만 보고도 조직을 구분할 수 있습니다.

"서브넷 마스크는 1의 개수를 조절해 '우리 동네'의 크기를 정하는 칼날이다. /28(240)로 자르면 16명씩 소그룹으로 묶여, 옆방의 불필요한 트래픽 간섭 없이 우리끼리 쾌적하게 통신할 수 있다."

TCP / UDP
일반적으로는 TCP만 사용한다 (웹서핑)

1. L2 스위치 (데이터 링크 계층)
기준: MAC 주소를 봅니다.

임무: 같은 동네(서브넷) 안에서 데이터를 옆집으로 배달하는 단순 배송 담당입니다.

비유: 아파트 경비실에서 우편함 호수를 보고 편지를 넣어주는 것과 같습니다.

2. L4 스위치 (전송 계층)
기준: **IP 주소 + 포트 번호(TCP/UDP)**를 봅니다.

임무: 서버 한 대가 감당하기 힘든 엄청난 트래픽을 여러 대의 서버로 나누어 주는 로드 밸런싱(Load Balancing) 담당입니다.

비유: 맛집 입구에서 손님들을 여러 개의 테이블로 안내하며 "저쪽 테이블이 비었으니 그리로 가세요"라고 교통정리 하는 지배인과 같습니다.

 => L4 스위치는 '어떤 서비스(Port)'인지 확인하고 '어떤 서버가 한가한지'까지 판단해서 데이터를 똑똑하게 나누어 준다."

TCP vs UDP 핵심 비교가장 큰 차이는 **"상대방이 받았는지 확인하느라 시간을 쓰느냐, 아니면 그냥 내 속도대로 냅다 던지느냐"**에 있습니다.
구분		TCP (Transmission Control Protocol)		   UDP (User Datagram Protocol)
별명		신뢰의 트럭 (안전 배송)					 	속도의 오토바이 (퀵 배송)
연결 방식	 연결 지향 (3-way Handshake)				비연결형 (상대 확인 안 함)
신뢰성		매우 높음 (분실 시 재전송)						낮음 (분실해도 그냥 진행)
순서 보장	번호를 매겨서 순서대로 조립						순서가 뒤바뀔 수 있음
속도		상대적으로 느림 (확인 절차 때문)			매우 빠름 (오버헤드가 거의 없음)
헤더 크기	최소 20 Byte (복잡함)						딱 8 Byte (매우 간단함)

TCP가 필요한 순간 (정확도가 생명!) : 이메일, 파일 전송(FTP), 웹 서핑(HTTP)
UDP가 필요한 순간 (속도가 생명!) : 실시간 스트리밍 / 보이스톡, 온라인 게임
